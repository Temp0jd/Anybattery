# AnyBattery UI 精细化、动效与 Bug 修复实施计划

日期：2026-10-26  
执行分工：主代理负责审查、规划、验收；实现代码由 DeepSeek V4.1 Flash subagent 修改。

## 1. 目标与原则

在保留现有产品行为与视觉识别的前提下，完成一轮可审查、可编译、可回退的小步打磨：

- 保留八位堂式像素风：暖色塑料底、硬边框、零圆角、像素电量格、Fusion Pixel 字体。
- 提升信息层级、间距、窄窗口布局、文字对比度与控件反馈，不改成通用圆角卡片或 Web 风格。
- 添加短促、克制、事件驱动的小动效；关闭“动画”后全部立即到位。
- 只修高置信度 UI、设置和托盘状态 Bug，不顺手重构 Windows/HID 协议实现。
- 优先复用 egui 0.37 已有能力，不新增依赖，不引入新的线程或异步运行时。

## 2. 已验证基线

- Git 初始工作区干净。
- `cargo test -p anybattery-core`：12 项测试通过。
- `cargo xwin check -p anybattery-app --target x86_64-pc-windows-msvc`：通过，有既有警告。
- `rustfmt` 组件已补装；全局 `cargo fmt --all -- --check` 在修改前即失败，既有格式 diff 约 2,007 行并分布在 core、Windows 与 app，本轮不得借格式化扩大改动范围。
- 当前环境不能替代 Windows 真机验证；HID、蓝牙、托盘和实际 DPI 观感必须在交付说明中保留验证边界。

## 3. 本轮 Bug 清单

### P0：状态与行为正确性

#### B1. 扫描期间修改显示设置可能长期保留旧结果

位置：`crates/anybattery-app/src/app.rs` 的 `request_scan`、`poll_results`、`settings_page`。

`request_scan` 在 `scanning == true` 时直接返回。“显示无电池设备”和“恢复默认”在扫描期间修改后请求刷新会被吞掉，正在执行的扫描仍使用旧 `Settings`，结果可能等到下一个轮询周期才纠正。

要求：

- 对上述设置变更，在当前扫描结束后排队且只排队一次重扫。
- 不并发执行多个 HID 扫描，不因自动轮询形成持续重扫循环。
- 普通“立即刷新”在扫描中可禁用或保持无操作，不必重复排队昂贵扫描。
- 扫描线程/通道失败时要离开 scanning 状态并给出已有风格的提示。

#### B2. 设置保存造成多余磁盘写入与主题重应用

位置：`app.rs` 的 `save_settings`、刷新间隔滑块、`new`。

- 滑块拖动期间每个 `changed()` 都写配置，且 `save_settings` 无条件令 `applied_dark = None`，导致无关设置变化也重应用主题。
- `applied_animations` 初始写死为 `Some(true)`，没有反映实际设置。

要求：

- 拖动时值与标签即时更新，配置在拖动结束时提交；键盘/其他非拖动变更也须能提交。
- 通用保存不再使主题失效；主题切换仍即时生效，动画开关仍即时生效。
- `applied_animations` 用真实初始设置初始化。

#### B3. 恢复默认可能让自启设置与注册表状态不一致

位置：`app.rs` “恢复默认”。

当前忽略 `system::set_autostart(false)` 的失败，仍保存 `autostart = false`。

要求：

- 失败时不得假装开机自启已关闭。
- 可中止恢复并提示，或恢复其他默认值但保留真实自启状态并明确提示；行为要一致、可审查。
- 托盘勾选项与最终设置保持同步。

#### B4. 没有可用百分比设备时托盘图标可能停在旧电量

位置：`app.rs` 的 `update_tray`。

`lowest == None` 时只更新 tooltip，不重置图标。

要求：设备消失、全部变为非 live 或没有百分比时，恢复无电量/默认托盘图标；有设备时的最低电量与充电颜色逻辑不变。

### P1：可直接确认的 UI/UX 缺陷

#### B5. 空状态文案不区分“没有设备”和“筛选无结果”

位置：`app.rs` 的 `devices_page`、`empty_state`。

- 其他筛选下有设备、当前筛选为空时，也显示“未发现带电池的设备”。
- “有线设备不会显示”与 `Transport::Usb` 及扫描实现不一致。

要求：分别处理扫描中、全局无设备、筛选无结果；文案准确，并提供返回“全部”或检查设置/诊断的明确引导。不得声称有线设备必然不显示。

#### B6. 页脚与诊断摘要的时间格式不一致

位置：`widgets.rs` 的 `footer`、`app.rs` 的诊断摘要。

当前页脚把 300 秒显示为“每 300 秒”，扫描中还混入英文 `SCANNING`。

要求：复用统一的间隔格式化逻辑，显示“30 秒 / 1 分钟 / 5 分钟”等自然中文；扫描、刚刚刷新、分钟前等状态一致。

#### B7. 卡片具有点击外观但没有点击行为

位置：`widgets.rs` 的 `device_card`。

当前使用 `Sense::click()`，却只实现 hover tooltip。

要求：本轮不扩展复杂详情页；移除错误的点击 affordance，保留完整 hover 信息。若实现键盘/触摸详情，应作为独立功能，不在本轮夹带。

#### B8. 固定字符数截断不能避免像素级重叠

位置：`widgets.rs` 的 `device_card`、`settings_row`，以及诊断/页脚等长文案区域。

名称、详情按 15/24/30 字符截断，未考虑中英文宽度、字体度量和右侧百分比/开关宽度；在最小窗口 380×520 或长设备名下可能侵入右侧区域。

要求：

- 以实际可用像素宽度布局/截断，而不是仅靠固定字符数。
- 卡片名称/详情、设置行标题/说明、页脚与诊断按钮在最小宽度下不互相覆盖。
- 卡片 tooltip 保留完整名称、来源、路径等详情。
- 不为解决重叠引入多行卡片导致列表高度不可控。

#### B9. 粗粒度电量格与设计语义不一致

位置：`widgets.rs` 的 `coarse_pixel_battery`。

设计为低/中/满三段，但当前画四格且 Full 只填三格。

要求：使用清晰的三段低/中/满表现，Full 显示满三段；不换算或展示伪造百分比。

#### B10. 小字对比度不足

位置：`theme.rs` 的 `Palette`、分段控件与选中按钮。

测得当前对比度：浅色 tertiary/card 约 2.70:1，深色 tertiary/card 约 3.26:1，深色选中文字/accent 约 3.29:1。tertiary 被用于有实际意义的说明与状态，不只是装饰。

要求：

- 提高浅色/深色辅助文字对比度，正常小字目标至少 4.5:1。
- 为 accent 上的文字使用明确的 `on_accent` 或等效语义色，深浅主题均保证可读。
- 保持原有暖色与像素风，不通过把所有文字都变成主文本色来偷懒；可保留更弱色仅用于非信息性装饰。

## 4. UI 精细化方向

实施可在以下文件内做局部重构：`app.rs`、`widgets.rs`、`theme.rs`、`icons.rs`。

1. **页头**：减少当前独立按钮条造成的空白，让标题与刷新/设置动作形成清晰一行，副标题另起一行；窄窗口不挤压动作区。
2. **卡片**：维持紧凑密度与硬描边，统一 8px 左右的间距节奏；让设备名、状态详情、百分比和电量格形成稳定左右栏。休眠/过期/错误/未识别状态须有可辨且不只依赖颜色的文字或小型状态标记。
3. **筛选与按钮**：统一 normal/hover/pressed/disabled 反馈；选中态清楚，刷新中具备明确状态。最终像素坐标保持锐利，不引入圆角、模糊阴影或渐变。
4. **设置页**：控制项对齐，说明文字可读，预设按钮与分组间距统一；避免为了美化改变现有设置语义。
5. **诊断页**：保留日志密度与复制能力，改善摘要和按钮布局；长日志可滚动，不撑破窗口。
6. **Toast**：保持现有像素框样式，位置不覆盖主要操作，文本长度受限且可读。

以上允许做审美判断，但必须服从“保留像素 identity、最小窗口不重叠、信息真实”三条硬约束。

## 5. 小动效规格

动效应是反馈，不是持续装饰。建议总时长 80–180ms，可按 egui 现有 animation API 调整。

- 分段选择：选中底色/指示位置短过渡。
- 按钮与卡片 hover/press：轻描边、底色或 1px 级别的视觉反馈，不造成布局跳动。
- 电量格：扫描得到不同百分比时，仅填充宽度/格数做短过渡；百分比数字保持真实目标值，不逐帧展示虚构读数。
- 刷新：仅在扫描中显示克制的旋转/步进反馈；扫描停止后立即稳定。
- Toast：短促淡入/淡出或 2–6px 位移，超时后彻底消失。

硬性要求：

- `settings.animations == false` 时无补间、无持续旋转、无额外高频 repaint。
- 空闲时不为装饰动画永久 60fps 重绘；使用 egui 动画自身的重绘调度或有限的 `request_repaint_after`。
- 不为动画引入设备状态副本的复杂新架构；使用稳定 device/control ID，避免排序或筛选后串用其他设备的动画状态。
- 不做闪烁低电量、循环卡片漂浮、长 stagger、视差等高干扰效果。

## 6. 明确不做

- 不实现跨扫描缓存、休眠恢复、Stale/Cached 状态机；这是独立架构与真机验证任务。
- 不修改 HID、蓝牙、Xbox 或厂商协议解析，不借本轮清理 unsafe Windows 警告。
- 不处理当前未使用的 `ScanResult.controller_count`。
- 不增加协议、新设置页、语言切换、Toast 系统通知或单实例功能。
- 不做大规模模块搬迁，不新增 UI 框架或重型测试依赖。
- 不执行会改写全仓或整个无关文件的自动格式化；只保持本次修改区域风格一致，既有格式债单独记录。
- 不提交 Git commit，不改 release 产物，不声称已完成 Windows 真机验证。

## 7. 验证与验收

实施者必须运行并报告实际结果：

```bash
export PATH=/home/tempo/.cargo/bin:$PATH
cargo test -p anybattery-core
cargo test --workspace --all-targets
cargo xwin check -p anybattery-app --target x86_64-pc-windows-msvc
cargo fmt --all -- --check
```

`cargo fmt --all -- --check` 只作为信息性检查：必须报告它在本轮前已失败，不得为让它通过而格式化全仓，也不得把该既有失败写成“通过”。保持本次修改区域的格式与周围代码一致，并运行 `git diff --check` 检查空白错误。新增逻辑若能低成本抽成纯函数，补最小单测；不要仅为测试做大型重构。

主代理验收清单：

- 只修改计划允许的范围，diff 无协议层或无关清理。
- Windows 目标编译通过，core 测试保持通过，`git diff --check` 通过；全局 rustfmt 的既有失败已如实记录，且没有格式化造成的无关 diff。
- 上述 B1–B10 均有对应代码证据；无只改文案却遗漏状态逻辑的情况。
- 动画开关能控制所有新增自定义动画，空闲无新增永久高频 repaint。
- 380×520 与 430×680 的布局代码有明确宽度约束；长中文/英文名不会侵入右侧控制区。
- 浅色/深色选中态和辅助文字对比度经复算达到目标。
- 最终说明区分：已自动验证、仅静态审查、仍需 Windows 真机验证。

建议 Windows 真机手测矩阵：

- 380×520、430×680；100%/125%/150% DPI。
- 浅色/深色/跟随系统；动画开/关。
- 全部/蓝牙/2.4G/手柄筛选及空筛选返回。
- 扫描中切换“显示无电池设备”；拖动与键盘修改刷新间隔。
- 扫描中、无设备、插拔最后设备和休眠设备的托盘图标。
- 恢复默认时注册表失败的提示与自启状态（可模拟失败环境时验证）。
- 长设备名、无电量设备、粗粒度电量、充电/满电/休眠/过期/错误状态。
